How it works — modes & scoring

Quick version: you write Prisoner's Dilemma strategies that return 'C' (Cooperate) or 'D' (Defect) each round. In the OS Simulation the same moves mean yield the CPU and keep running. Strategies compete in three modes — 1v1, N-Player, and a standalone OS Simulation. Open a section below for the details.
The three modes
  • 1v1 — round-robin: every strategy plays every other in a separate two-player match. Ranked by total points (highest first).
  • N-Player — one group match where everyone moves at the same time each round. Also ranked by total points (highest first).
  • OS Simulation — a standalone benchmark scored on scheduling metrics (throughput, wait, turnaround, response, cache misses). Ranked by average response time (lowest first): how long a task waits before it first gets the CPU.

Each results table says what it is ranked by. When two strategies tie, they are split by wins, then cooperation % (OS Simulation: waiting time, then throughput), then by who submitted first. If they are still equal, the earlier entry stays ahead. The admin can pick a different ranking for a round, and the results page then shows that one.

The weighted score (optional ranking for 1v1 & N-Player)

Each strategy earns three component scores, each a fraction from 0 to 1:

  • Win rate — wins / (wins + draws + losses). Each opponent (1v1) or group match (N-Player) is one game; the winner is whoever has the higher average points per round.
  • Points — your average points per round, divided by the best possible single-round payoff. A throughput proxy.
  • Cooperation — your cooperation rate, averaged across the selected modes (each mode weighted equally).

The final Weighted Score adds each fraction × its weight, scaled to 100:

Score = (win_rate · Wwin + cooperation · Wcoop + points · Wpoints) × 100

Weights are set when the tournament is configured. Because points use a per-round average, win rate counts once per opponent, and cooperation weights modes equally, match length never biases the score.

A strategy must return exactly 'C' or 'D'. One that crashes, loops forever, or returns anything else (e.g. 1, None, 'c') is disqualified. It is removed from the ranking, its matches do not count for anyone, and the results say which strategy failed and why.

Match-length modes
  • Standard — a fixed number of rounds; payoffs added normally.
  • Discounted — later rounds count for less (discount_factort).
  • Stochastic — after round 1 the game continues with probability stochastic_prob each round, so length varies.
  • Random Iterations — a seeded random round count; scores are normalised so the length doesn't bias results.

Pick several and the tournament runs once per mode, then aggregates the scores.

N-Player payoff models
  • Public Goods — each cooperator pays a cost c; the shared pool pays everyone back. With k cooperators among n players, a cooperator nets (b·k)/n − c and a defector nets (b·k)/n.
  • Pairwise Matrix — each player plays the 2-player matrix against every other in the group; per-round results are summed or averaged.
  • K-Cooperator Tensor — payoff depends only on how many cooperated: a cooperator gets u_C[k], a defector gets u_D[k].
How the OS simulation works

A standalone benchmark (separate from the tournaments). Each strategy becomes the scheduling personality of a simulated multi-core CPU, and we measure how well it schedules a workload.

  • Cores — choose 2–8. At each dispatch a core plays one PD move against a shared contention signal: it sees Defect when the system is congested (ready queue longer than the core count, or most other cores are defecting), otherwise Cooperate. Cooperate = yield the CPU; Defect = keep running.
  • Assignment — Homogeneous tests one strategy on all cores; Heterogeneous mixes different strategies across cores and ranks the mixtures.
  • Baseline — each run also executes the plain textbook scheduler (cores never yield) for reference, so you can see what the strategies add.
  • Cooperation — each strategy's realised Cooperate rate is reported, to line up with the 1v1 / N-Player cooperation metric.

The workload dataset

Each run uses a seeded, synthetic dataset of 50 processes (same seed ⇒ same dataset). Every process has:

  • Arrival time — when it joins the ready queue.
  • CPU burst — how many ticks of CPU it needs.
  • Memory working set — a per-process footprint (log-normal, median 4 KB, clamped 1–32 KB) that generates a memory-access stream driving cache hits/misses.

Four profiles model different real-world load shapes:

ProfileArrivalsCPU bursts
Uniformevery 15 ticks (steady)flat 30–80 (light-tailed)
Poissonexponential, mean 20 tickslog-normal (median 45, σ 0.6), clamped 10–400
Mixedevery 10 ticks80% short (median 20) + 20% long (median 280)
Burstybatches of 10, every 300 tickslog-normal (median 35, σ 0.55)

Why these: real CPU service times are heavy-tailed (most jobs short, a few very long), so bursts use a clamped log-normal and arrivals use the Poisson model. Together the four span light/steady, random, interactive-plus-batch and spiky loads.

How the simulation runs & records metrics

The simulator advances one tick at a time. Each tick:

  1. New processes (arrival time reached) enter the ready queue.
  2. The scheduler does housekeeping (MLFQ boosts, affinity load-balancing).
  3. Each free core plays its PD move, the scheduler picks the next job, and it runs one tick. Cache stalls slow progress.
  4. On completion, the process's timing is recorded.

Metrics (over n finished jobs and T ticks):

turnaround = completion − arrival Avg Turnaround = mean(turnaround) waiting = max(0, turnaround − burst) Avg Wait = mean(waiting) response = first_start − arrival Avg Response = mean(response) Throughput = n / T × 1000 (jobs per 1000 ticks) Cache Misses = (per-core L1+L2 misses + shared-L3 misses) / n Makespan = T Cooperation % = cooperate moves / total moves

Lower is better for wait / turnaround / response / cache; higher is better for throughput / cooperation. Each metric is computed per profile, then averaged across the four. Give a Seed to make a run fully reproducible.
